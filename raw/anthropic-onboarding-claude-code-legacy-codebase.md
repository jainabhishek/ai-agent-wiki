## Introduction
- Skyline: open-source protein detection and quantification software
  (biomarker discovery, disease research, drug development), developed since
  2008.
- Codebase: 700,000+ lines of C#, maintained 17 years by a small team, 200,000+
  automated nightly tests.
- MacLean has onboarded dozens of undergrads, grad students, and postdocs. By
  2024 some areas of the code had become "untouchable" as developers left.

## The same onboarding problem, a different kind of developer
- Early use of Claude.ai in the browser: describe a problem, paste back whole C#
  files; workable only for contained problems; laborious once changes became
  incremental, and every session started from zero.
- Idea: introduce Claude (via Claude Code) the way he introduces a trainee —
  explain enough for a limited successful project, and produce better context
  for the next iteration.
- All AI context lives in a separate repository, `pwiz-ai`, so it applies
  across all branches and points in time.
- Root `CLAUDE.md` handles environment setup and points to docs — the "lay of
  the land", not the expertise.
- Expertise lives in skills. The `debugging` skill pushes Claude out of "guess
  and test" mode toward root-cause analysis before a fix. Critical skills get
  explicit trigger conditions; the `debugging` description says to always load
  it when investigating bugs, failures, or unexpected behavior.
- MacLean's conclusion (paraphrased): context is an artifact to maintain and
  grow.

## Reducing tech debt and accelerating development
- A year-long, unfinished Files View panel (file system monitoring,
  drag-and-drop) left behind by a departed developer was finished in two weeks
  with Claude Code; all final commits co-authored by Claude. Previously such
  abandoned work was usually discarded.
- Nightly test management module (Java, on LabKey Server), frozen for three
  years after its maintainer left: after a LabKey developer wrote setup docs
  with Claude Code, MacLean added long-wanted features and updated CSS layout in
  under a day.
- Tutorial screenshot reproduction for 2,000+ images is fully automated and
  nearly 100% reproducible, extended with diff-only views and pixel change
  amplification, plus a C# MCP server (written by Claude) so Claude can "see"
  the diffs.
- A daily morning summary generated by Claude Code: test failures, exceptions,
  open support threads; backed by a Python MCP server (written by Claude) over
  three data streams: LabKey Server relational data, team email, GitHub code
  with release tags.
- Lab developers now mostly instruct Claude Code rather than write code; a
  previously skeptical developer shipped a mobilogram pane (ion mobility
  visualization) with it.

## Advice for developers working on legacy codebases
- Context is your best friend: Claude's to-do lists and plans do not persist
  across sessions; recorded context does, and must be maintained deliberately.
  Version it, grow it, maintain it like any project artifact. Separate repo
  because context grows at a different speed than code and spans branches; the
  same repo is a valid alternative.
- Invest in building your skill library: "reference do not embed" — each skill
  points into a central documentation knowledge base instead of duplicating it.
  Most-used skills: `skyline-development` (project orientation),
  `version-control` (commit and PR conventions), `debugging` (root cause first).
- Use MCP integrations when data access is key: test results, exception
  reports, support threads.
- For open source: no onboarding budget, no institutional memory beyond what is
  written; `pwiz-ai` is itself an open-source artifact owned by the project.

## Seventeen years of onboarding, one conclusion
- Treat Claude like a new hire: a contained project first, then wider scope as
  understanding grows. With enough context, Claude can work across branches and
  points in time like an experienced engineer.
